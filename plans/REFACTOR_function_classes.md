# Plan: refactor `data/function_classes.csv` (tighten two classes, add new ones)

Status: **plan only** (decision D6, 2026-11-11). `function_classes.csv` and `assays.csv` are expert-curated; nothing has been edited. All numbers are from UniProt's reviewed human proteome (20,429 proteins, downloaded 2026-11-10), classified with the pipeline's own rules (`m4_recommend.classify`). Re-measure with `py tools\audit_gaps.py --uniprot-tsv …`.

## 1. What a change to function classes touches (follow-up actions)

A class is not just a row in one file. Changing, adding or renaming a class affects all of these:

| # | Where | What happens today | Follow-up needed |
|---|---|---|---|
| 1 | `scripts/build_database.py` `step_summary` | Each protein's classes are computed **once** and frozen in `build_cache/summary/<acc>.json`. Editing `function_classes.csv` does **not** trigger a recompute (only `term_table.csv` edits do). | **Code change (do first):** recompute classes during the aggregate step from the cached UniProt entry (`build_cache/m1_data/uniprot_<acc>.json`, already on disk). Class edits then take effect with `--aggregate-only`, with no relabeling or downloads. Add a test. |
| 2 | `data/usage_stats.csv` (rows with `scope_type = function_class`) | Rows for a removed or renamed class stay behind; `tools/build_db.py` then **stops with an "unknown class" error**. | **Code change:** in `merge_into_data`, drop automatic rows whose class no longer exists (hand-made rows: report them, don't delete). Add a test. |
| 3 | `data/assays.csv`, `classes` column | A new class with no playbook entry gets only the generic assays (G1–G7) on the site. | **Curator:** add entries or add the new class to existing entries (for example, put `lipid_kinase` on K1–K6). |
| 4 | `scripts/term_table.csv` (function terms) and `assays.csv` `evidence_labels` | Campaigns only count toward an entry when their function label matches `evidence_labels`. New classes need function terms (e.g. "Phosphodiesterase activity", "Dehydrogenase activity", "GTPase activity"). | **Curator + me:** add terms with synonyms and an example sentence. Editing the term table relabels automatically on the next build (no downloads). |
| 5 | `docs/index.html` `classifyProtein` | A JavaScript copy of `m4.classify` runs on live UniProt look-ups. It reads the rules from `assay_db.json`, so new rules apply automatically, but the two copies must behave the same. | **Me:** a parity check — run both on the same ~50 UniProt entries and compare (Python side via `tools/audit_gaps.py`; JS side via the headless-browser harness used in the audit). |
| 6 | `docs/demo_proteins.json` | Built-in fallback copies (GLP1R, HDAC1, …) store **pre-computed** classes. | **Me:** regenerate the file after the rules change. |
| 7 | `data/condition_stats.csv`, `build_output/effect_by_class.csv`, `function_gaps.csv`, `readout_suggestions.csv`, `build_output/audit/*` | Generated per class. | Regenerated by `--aggregate-only --merge` and `tools/audit_gaps.py`; nothing manual. |
| 8 | `data/kits.csv` | Kits link to entries, not classes. | None, unless new entries get kits. |
| 9 | Website text | The Definitions entry "How function classes are found" lists the rule types. | Update if rule types change (e.g. InterPro IDs). |
| 10 | `schema/assay_db.schema.json`, README | Describe the class fields. | Update only if new rule columns are added (see 4.2). |

Rule of thumb: **never rename a `class_id`.** Add a new one and retire the old one, so old rows and links don't break.

## 2. Tightenings (fix false members)

| Class | Change | Effect | Watch out |
|---|---|---|---|
| `protein_kinase` | `keywords`: `kinase` → `Serine/threonine-protein kinase\|Tyrosine-protein kinase`; keep EC 2.7.10–2.7.13, GO "protein kinase activity" and the "protein kinase" domain | 680 → 542 proteins; removes 138, 90 of them with campaigns: metabolic kinases (PGK2, PFKM, AK1, CKM, TK1/TK2, NADK, PDXK, XYLB, NME4/6, PRPS2) **and lipid kinases** (PIK3CD, PIK3C2A/B/G, PIP5K1B/C, DGKI, PPIP5K2) | Lipid kinases are major drug targets and use the same assay platforms (ADP-Glo, HTRF, TR-FRET). **Do not drop them silently: add `lipid_kinase` (see 3).** |
| `ion_channel` | `go_terms`: drop `channel activity`, keep `ion channel activity` | 490 → 390; removes 100, 41 with campaigns: aquaporins (AQP2/7/8/9, MIP), FXYD1, gasdermin GSDME, perforin PRF1, BCL2, OPRM1 (already a GPCR), ATP synthase subunits (MT-ATP6, ATP5MC1), RHCE, PSEN1 | CLCN3/CLCN4 (CLC chloride/proton antiporters) and SCN2B (Na-channel β subunit) also drop out. Curator decides: re-add via keyword `Chloride channel` or a short include list. |

Also check (not measured yet):

- `receptor_ectodomain` (1,610 proteins, `needs_domain = yes`). Very broad; it includes many adhesion and immune receptors with no ligand-blocking assay history.
- `ppi_domain` (1,527). Any protein with an SH2/SH3/PDZ/WD40/… domain qualifies. Consider requiring a known interaction partner or ChEMBL target.
- `rna_binding` (1,653). Includes ribosomal proteins and splicing machinery; consider excluding keyword `Ribonucleoprotein` without a druggable domain.

## 4. Work plan (in order)

1. **Code first** (no data change):
   1. Recompute classes in the aggregate step (table row 1).
   2. Drop orphaned automatic class rows in `merge_into_data` (row 2).
   3. Python ↔ JavaScript parity check for `classify` (row 5).
   4. Tests for all three.
2. **Optional new rule columns.** If needed, add `interpro_ids` (exact, more precise than domain names) and `include_genes` / `exclude_genes` (short curated lists for edge cases like CLCN3 or OPRM1). These touch `m4.classify`, `index.html` `classifyProtein`, `tools/build_db.py` and the schema.
3. **Curator, tightenings:** edit the `protein_kinase` and `ion_channel` rows; add `lipid_kinase`; put `lipid_kinase` on K1–K6 in `assays.csv`.
4. **Curator, expansions, in priority order:** `phosphodiesterase`, `small_gtpase`, `oxidoreductase`, `transferase_other`, `transcription_factor`. For each: a class row, 2–4 playbook entries (primary / confirmation / counterscreen), function terms in `term_table.csv`, and `evidence_labels`.
5. **Rebuild** (all local, no downloads):
   ```powershell
   py scripts\build_database.py --aggregate-only --merge       # relabels only if term_table.csv changed
   py tools\build_db.py
   py tools\audit_gaps.py --uniprot-tsv "$env:TEMP\human_reviewed.tsv.gz"
   ```
   Then regenerate `docs/demo_proteins.json`.
6. **Acceptance checks:**
   - `tools/build_db.py` builds with no errors.
   - The parity check passes.
   - Spot-check 10 proteins per changed class on the site (PIK3CA, PGK1, AQP2, KRAS, PDE4B, IDH1, STAT3 …).
   - In `gaps_by_class.csv`, every new class has entries and a non-zero campaign count.
